# Repository Analysis: SSAMBA (Self-Supervised Audio Mamba)
> Generated by ML Repo Analyst | 2026-03-25

## Overview

SSAMBA is a PyTorch research implementation of **self-supervised audio representation learning** that replaces the Vision Transformer (ViT) backbone of SSAST with **bidirectional Mamba State Space Model** blocks from Vision Mamba (Vim). The system pretrains on unlabeled audio from AudioSet + LibriSpeech via masked patch prediction (both discriminative and generative objectives), then fine-tunes on six downstream audio classification tasks. Published at IEEE SLT 2024 (arXiv:2405.11831), it claims ~92.7% faster batch inference and ~95.4% lower GPU memory usage versus the SSAST baseline.

This is a compact research codebase (~50 source files) with a single primary workflow: pretrain an audio Mamba encoder, then fine-tune it on a downstream task. The architecture is straightforward and the codebase is well-scoped.

## Architecture & ML Concepts

### Model Architecture

The core model is `AMBAModel` (in `src/models/both_models.py`), which wraps a **Vision Mamba** (`VisionMamba`) encoder. The data flow is:

```
Raw Audio (.wav)
  --> torchaudio Kaldi-compatible log-mel filterbank (128 mel bins)
  --> Pad/crop to target_length frames (e.g., 1024 for pretraining, 512 for ESC-50)
  --> SpecAugment (frequency masking + time masking) + optional mix-up
  --> Normalize with dataset mean/std
  --> [1, 128, target_length] spectrogram treated as a single-channel "image"
  --> Conv2d patch embedding (16x16 patches) --> token sequence
  --> Prepend CLS token + add positional embeddings
  --> Bidirectional Mamba blocks (forward + backward pass per layer pair)
  --> RMSNorm / LayerNorm final normalization
  --> Task head (classification MLP or masked patch prediction heads)
```

**Bidirectional Mamba processing** is the key architectural innovation. The model allocates pairs of Mamba layers: even-indexed layers process the sequence forward, odd-indexed layers process it reversed (`.flip([1])`). Their outputs are summed, giving each token context from both directions -- critical for non-causal audio understanding tasks where the entire spectrogram is available.

### Pretraining Strategy (Self-Supervised)

Three pretraining objectives are supported, selected via `--task`:

1. **`pretrain_mpc`** (Masked Patch Classification -- discriminative): Mask N patches with learnable mask embeddings, encode the full sequence, predict the original flattened patch content via NCE contrastive loss. The prediction head maps transformer output to 256-dim space and computes dot-product similarity with the true 256-dim patch values. Negatives come from other masked patches in the same sample.

2. **`pretrain_mpg`** (Masked Patch Generation -- generative): Same masking, but reconstruct the masked patch pixel values directly via MSE loss. Uses a separate `gpredlayer` prediction head.

3. **`pretrain_joint`** (Joint): Runs both MPC and MPG, combining losses as `loss_mpc + 10 * loss_mpg`. This is the **default and recommended pretraining task** per the shell scripts.

Masking uses **cluster masking** for 16x16 patches (spatially correlated mask regions, randomized cluster factor 3-6) and simple random sampling for frame-level patches.

### Fine-tuning Strategy

Fine-tuning loads pretrained weights, re-initializes the patch embedding stride (allowing overlap for denser token sequences), interpolates positional embeddings to match new sequence lengths, and adds a classification MLP head (`LayerNorm -> Linear`). Two fine-tuning modes:

- **`ft_avgtok`** (default): Mean-pool all non-CLS token outputs as the clip-level representation
- **`ft_cls`**: Use only the CLS token output

The optimizer is Adam with differential learning rates (MLP head can use `head_lr` multiplier). LR scheduling is either `MultiStepLR` (default) or `ReduceLROnPlateau` (adaptive). Linear warmup over the first 1000 steps is standard.

### Data Pipeline

`AudioDataset` in `src/dataloader.py` reads JSON manifest files with format `{"data": [{"wav": "/path/to/audio.wav", "labels": "label_id"}, ...]}`. For each sample:

1. Load waveform via `torchaudio.load`
2. Optionally mix-up with a random sample (Beta(10,10) mixing coefficient)
3. Compute log-mel filterbank via `torchaudio.compliance.kaldi.fbank` (128 mel bins, 10ms frame shift, Hanning window)
4. Pad/crop to target length
5. Apply SpecAugment (frequency masking `freqm`, time masking `timem`)
6. Normalize: `(fbank - mean) / (std * 2)`
7. Optional noise augmentation (additive random noise + random time-roll, used for Speech Commands)

### Evaluation

Validation computes per-class AP, AUC, accuracy, precision, recall, and d-prime. The system supports:
- **Prediction ensembling**: Cumulative averaging of predictions across epochs
- **Weight averaging** (`--wa`): Averages model checkpoints from `wa_start` to `wa_end` epochs
- Best model selection on validation metric (mAP or accuracy depending on dataset)

## Key Workflows

### Golden Path: Pretrain then Fine-tune

**Step 1 -- Data Preparation:**
```bash
cd src/prep_data
python prep_audioset.py        # Generate AudioSet JSON manifests
python prep_librispeech.py     # Generate LibriSpeech JSON manifests
python mix_pretraining_data.py # Merge into combined pretraining JSON
```

**Step 2 -- Pretraining:**
```bash
cd src/pretrain
# Edit run_mask_patch_amba.sh to set data paths, then:
./run_mask_patch_amba.sh
# Trains joint MPC+MPG objective, 300 masked patches, base model
# Saves checkpoints to exp/ directory
```

**Step 3 -- Fine-tuning (e.g., ESC-50):**
```bash
cd src/finetune/esc50
./run_esc_patch_amba.sh ssamba_base_300
# Runs 5-fold cross-validation, 50 epochs per fold
# Results aggregated by get_esc_result.py
```

**Step 4 -- Inference Benchmarking:**
```bash
cd src/inference
python inference_amba.py --model_size base
# Sweeps input sizes from 1024 to 151680 frames, measures time and memory
```

## Dependencies & Environment

**Core ML stack:**
- PyTorch 2.2.2 + torchaudio 2.2.2
- `mamba_ssm` 1.2.0.post1 (Mamba selective scan CUDA kernels)
- `causal_conv1d` 1.2.0.post2 (1D causal convolution CUDA kernel, dependency of mamba_ssm)
- `timm` 1.0.3 (for `PatchEmbed`, `trunc_normal_`, model registry)
- `einops` 0.8.0

**External repo dependency:**
- **Vision Mamba (Vim)** must be cloned into the ssamba directory. Provides the `VisionMamba` model class and `models_mamba` module. This is imported at runtime via `sys.path.append`.

**SUPERB tasks (VoxCeleb1, IEMOCAP):**
- `s3prl` 0.4.15

**Hardware:** CUDA GPU required. Shell scripts reference SLURM with L40 GPUs. Pretraining uses batch_size=64; fine-tuning varies (48 for ESC-50). The efficiency gains over SSAST are most pronounced at long sequence lengths (>10K tokens).

## Notes & Observations

### Hardcoded Paths (Red Flag)
Multiple files contain hardcoded absolute paths to the original authors' environment:
- `src/models/both_models.py` lines 20-22: `sys.path.append('/home/ss6928/ssast/Vim')` -- This will fail on any other machine. Users must update these paths (or ensure Vim is on PYTHONPATH).
- `src/run_amba.py` line 20: `sys.path.append('/share/naplab/users/ss6928/ssast/modules')`
- Shell scripts reference `/engram/naplab/shared/` for data paths.

### Code Duplication
The bidirectional Mamba forward pass (the ~30-line block with forward/backward layer processing and fused_add_norm) is copy-pasted verbatim in five methods: `finetuningavgtok`, `finetuningavgtok_1sec`, `finetuningcls`, `mpc`, and `mpg`. This is fragile -- a bug fix in one must be replicated to all five.

### ASTModel as Dead Code
The `ASTModel` class (~400 lines) is defined in `both_models.py` but is never used by `run_amba.py`. It exists for baseline comparison via the separate `run.py` entrypoint. The `ASTModel` requires `timm==0.4.5` (asserted in its `__init__`), while `requirements.txt` pins `timm==1.0.3`, meaning ASTModel cannot actually be instantiated with the current requirements.

### Vim Import Fragility
The `VisionMamba` import is wrapped in a try/except that silently sets `RMSNorm`, `layer_norm_fn`, `rms_norm_fn` to `None` on failure. This means if Vim is not properly installed, the model will import without error but crash at runtime when `fused_add_norm=True` is set (which is the default in the config dict, though the shell scripts set it to `false`).

### No Unit Tests
There are no test files anywhere in the repository. Given the code duplication in the forward pass and the fragile import paths, this increases risk of silent regressions.

### Pretraining Scale
The pretraining scripts use `epoch_iter=4000` (checkpoint every 4000 steps) rather than epoch-based checkpointing, which is appropriate given the large pretraining dataset. The total pretraining is 10 epochs with batch_size=64.

### Weight Averaging Caveat
The `validate_wa()` function in `traintest.py` loads individual epoch checkpoints from disk, but the default training config has `save_model=False`, meaning per-epoch checkpoints are not saved. Weight averaging will fail unless `save_model` is set to `True`.

### WandB Integration
Both training scripts integrate with Weights & Biases for experiment tracking, gated behind `--use_wandb`. The pretraining shell scripts enable it by default.

### Design Pattern
This codebase follows the **SSAST/AST pattern** from Yuan Gong's MIT lab: a monolithic argparse entrypoint that builds everything procedurally, shell scripts as configuration surfaces, JSON manifests for data, and DataParallel for multi-GPU (not DDP/FSDP). This is a common pattern in audio ML research but would not scale to large distributed training without refactoring.
