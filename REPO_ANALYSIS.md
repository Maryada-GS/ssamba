# Repository Analysis: SSAMBA (Self-Supervised Audio Mamba)
> Generated by ML Repo Analyst | 2026-03-28

## Overview

SSAMBA is a PyTorch research codebase that replaces the Vision Transformer (ViT/DeiT) backbone in SSAST (Self-Supervised Audio Spectrogram Transformer) with bidirectional Mamba state space models from the Vision Mamba (Vim) project. The repo implements self-supervised pretraining via masked patch prediction on AudioSet + LibriSpeech, then fine-tunes the learned representations on six downstream audio classification tasks. The authors claim ~92.7% faster inference and ~95.4% less memory than the SSAST baseline. This is a research paper implementation targeting audio ML researchers who want to explore SSM-based alternatives to attention-based audio models.

## Architecture & ML Concepts

### Model Architecture

Two model classes share an identical API surface (same `forward(x, task, ...)` signature) and differ only in their encoder backbone:

**AMBAModel** (`src/models/amba_model.py`, ~984 lines):
- Backbone: `VisionMamba` from the Vim submodule (`Vim/vim/models_mamba.py`). This is a bidirectional Mamba architecture where pairs of Mamba blocks process the token sequence in forward and reverse directions. The forward pass manually iterates `self.v.layers` in pairs, flipping the sequence for the backward direction and summing residuals.
- Normalization: Supports both standard LayerNorm and fused RMSNorm (via Triton kernels from `mamba_ssm.ops.triton.layernorm`). The `fused_add_norm` flag toggles the fused kernel path.
- Position encoding: Trainable positional embeddings (not sinusoidal), with bilinear interpolation to handle different sequence lengths between pretraining and fine-tuning.
- CLS token: Single CLS token prepended to the sequence (no distillation token, unlike DeiT).

**ASTModel** (`src/models/ast_model.py`, ~726 lines):
- Backbone: `timm` DeiT models (`vit_deit_*_distilled_patch16_*`). Uses standard multi-head self-attention blocks.
- Hardcoded assertion for `timm==0.4.5` which conflicts with the actual installed `timm==1.0.3` in `pyproject.toml`. This will crash at runtime for the SSAST path.
- CLS token: 1 or 2 CLS tokens depending on model variant (DeiT distilled models have a distillation token).

Both models share:
- Patch embedding: 2D Conv2d projecting 1-channel mel-spectrogram patches into the embedding space.
- Three forward modes: `finetuningavgtok` (mean of all non-CLS tokens), `finetuningcls` (CLS token only), `finetuningavgtok_1sec` (per-second token averaging for UrbanSound8K).
- Two SSL pretext tasks: `mpc` (Masked Patch Classification -- discriminative NCE loss) and `mpg` (Masked Patch Generation -- MSE reconstruction loss).
- Mask generation: Clustered masking for 16x16 patches, random masking for frame-level patches. Uses BEIT-style learnable mask embeddings.

### Model Sizes

| Size  | embed_dim | depth |
|-------|-----------|-------|
| base  | 768       | 24    |
| small | 384       | 24    |
| tiny  | 192       | 24    |

Note: The `depth` here refers to the number of Mamba blocks. For bidirectional mode, blocks are consumed in pairs (forward + backward), so effective depth is `depth/2` bidirectional layers.

### Data Pipeline

`src/dataloader.py` -- `AudioDataset`:
- Reads JSON manifests with `{"data": [{"wav": "path.wav", "labels": "label1,label2"}, ...]}`.
- Computes 128-bin log-mel filterbank features via `torchaudio.compliance.kaldi.fbank` (Kaldi-compatible).
- Pads/truncates to `target_length` frames (e.g., 1024 for pretraining, 512 for ESC-50).
- SpecAugment: Frequency masking (`freqm`) and time masking (`timem`).
- Mix-up: Beta(10,10) distribution for waveform-level mixing with soft label blending.
- Normalization: `(fbank - mean) / (std * 2)` using dataset-specific statistics.
- Output shape: `[time_frames, mel_bins]` = `[1024, 128]` for pretraining.

### Training Pipeline

**Pretraining** (`src/traintest_mask.py` -- `trainmask`):
- Optimizer: AdamW with weight_decay=5e-8, betas=(0.95, 0.999).
- LR schedule: Linear warmup over first 1000 steps, then ReduceLROnPlateau.
- Validation frequency: Every `epoch_iter` steps (default 4000), not per-epoch -- because pretraining data is very large.
- Three pretext tasks: `pretrain_mpc` (discriminative), `pretrain_mpg` (generative), `pretrain_joint` (mpc + 10*mpg).
- Checkpoints: Best model + periodic saves at each validation step.
- Labels are ignored during pretraining (only spectrograms used).

**Fine-tuning** (`src/traintest.py` -- `train`):
- Optimizer: Adam with differential learning rates (MLP head can use `head_lr` multiplier).
- LR schedule: MultiStepLR or ReduceLROnPlateau (adaptive).
- Warmup: Linear over first 1000 steps.
- Loss: BCE (multi-label, AudioSet) or CE (single-label, ESC-50/SC/Urban8K).
- Evaluation: Per-class AP, AUC, accuracy, d-prime. Ensemble predictions across epochs.
- Weight averaging: Optional post-training weight averaging across epoch checkpoints.
- WandB integration for logging.

### Data Flow Summary

```
Raw .wav audio
  -> torchaudio.load() -> waveform
  -> optional mixup (waveform-level)
  -> kaldi.fbank() -> 128-bin log-mel spectrogram [T, 128]
  -> pad/truncate to target_length -> [1024, 128]
  -> SpecAugment (freq/time masking)
  -> normalize with dataset mean/std
  -> model.forward():
      -> unsqueeze(1) + transpose -> [B, 1, 128, 1024]
      -> Conv2d patch_embed -> [B, num_patches, embed_dim]
      -> prepend CLS token + add pos_embed
      -> Bidirectional Mamba blocks (AMBAModel) or ViT blocks (ASTModel)
      -> final norm
      -> task head (avg pooling + MLP for ft, NCE/MSE for pretrain)
```

## Key Workflows

### 1. Pretraining (Golden Path)

```bash
cd src/pretrain
./run_mask_patch_amba.sh  # SSAMBA pretraining
```

This runs `src/run.py --model amba --task pretrain_joint` with 16x16 patches, 300 masked patches, batch_size=64, lr=1e-4, on AudioSet+LibriSpeech combined data. Outputs pretrained weights to `exp/` directory.

### 2. Fine-tuning (e.g., ESC-50)

```bash
cd src/finetune/esc50
./run_esc_patch_amba.sh ssamba_base_300
```

Loads pretrained weights from `src/model_weights/ssamba_base_300.pth`, runs 5-fold cross-validation with `--task ft_avgtok`, CE loss, 50 epochs, batch_size=48.

### 3. Inference Benchmarking

```bash
cd src/inference
python inference_amba.py --model_size base
```

Sweeps input sizes from 1024 to 151680 frames, measures CUDA inference time and peak memory for each size.

### 4. SUPERB Tasks (VoxCeleb1, IEMOCAP)

```bash
cd src/finetune/voxceleb1
./run_sid.sh amba_patch400_base
```

Uses s3prl's `run_downstream` with custom upstream experts defined in `src/models/ssast/`. The upstream expert wraps AMBAModel/ASTModel as an s3prl-compatible feature extractor.

## Dependencies & Environment

**Core stack:**
- Python >=3.8, <3.12
- PyTorch 2.2.2 + torchaudio 2.2.2
- mamba-ssm 2.3.1 (state space model CUDA kernels)
- causal-conv1d 1.6.1 (1D causal convolution kernel for Mamba)
- timm 1.0.3 (for ASTModel's DeiT backbone -- NOTE: ASTModel asserts timm==0.4.5, which will crash)
- einops 0.8.0
- Vim submodule (cloned into repo root as `Vim/`)

**SUPERB tasks (optional):**
- s3prl (for VoxCeleb1/IEMOCAP downstream evaluation)

**Hardware:** CUDA GPU required for Mamba CUDA kernels and Triton-based normalization. SLURM headers in shell scripts request L40 or A40 GPUs with 32GB memory.

**Dependency conflict:** `requirements.txt` lists `mamba_ssm==1.2.0.post1` and `causal_conv1d==1.2.0.post2`, while `pyproject.toml` specifies `mamba-ssm==2.3.1` and `causal-conv1d==1.6.1`. The pyproject.toml appears to be the authoritative source.

## Notes & Observations

### Issues and Broken Code

1. **timm version conflict (ASTModel):** `ast_model.py` line 77 asserts `timm.__version__ == '0.4.5'`, but `pyproject.toml` installs `timm==1.0.3`. Any code path using `--model ssast` will crash immediately. The AMBAModel has this assertion commented out.

2. **Missing scripts (UrbanSound8K):** `urban_amba.sh` and `urban_ssast.sh` invoke `run_amba_1sec.py` and `run_ssast_1sec.py` respectively. Neither file exists. These tasks are non-functional.

3. **Missing resume script:** `resume_mask_patch_amba.sh` references `resume_amba.py` which does not exist.

4. **Duplicated model code (upstream_models.py):** `src/models/ssast/upstream_models.py` contains full copies of both AMBAModel and ASTModel (not imports from the canonical files). This is a maintenance hazard -- changes to the main model files won't propagate here.

5. **Double normalization in AMBAModel:** In `finetuningavgtok`, `finetuningcls`, `mpc`, and `mpg`, the code applies `self.v.norm_f(hidden_states)` inside the fused_add_norm branch, then applies `self.v.norm_f(hidden_states)` again on line 587/653/765/936. This means the final hidden states are normalized twice -- once via the fused path and once via a redundant explicit call. This is likely a bug that reduces model expressivity.

6. **Stale requirements.txt:** Dependency versions in `requirements.txt` are outdated compared to `pyproject.toml`. Also includes `interfaces==0.0.4` and `model_factory==0.0.8` which don't appear to be used anywhere in the code.

7. **Hardcoded normalization constants in audio.py:** `src/models/ssast/audio.py` line 102 hardcodes AudioSet normalization stats `(y + 4.2677393) / (4.5689974 * 2)` rather than accepting them as parameters. This means the s3prl upstream expert always uses AudioSet statistics regardless of downstream dataset.

8. **sys.path manipulation everywhere:** The codebase relies heavily on `sys.path.append()` and `sys.path.insert()` rather than proper Python packaging. This makes imports fragile and order-dependent.

9. **Mamba bidirectional pass is manually unrolled:** Rather than letting VisionMamba handle bidirectionality internally, AMBAModel reimplements the bidirectional forward pass by manually iterating layers in pairs and flipping sequences. This duplicated logic appears in 5 methods (`finetuningavgtok`, `finetuningavgtok_1sec`, `finetuningcls`, `mpc`, `mpg`).

10. **`nn` not imported in traintest_mask.py:** Line 42 references `nn.DataParallel` but the import is `from torch import nn` which is not present -- the file imports `torch` but not `nn` separately. However, `from utilities import *` pulls in `util.py` which does not export `nn`, so this would fail if `nn` isn't already in scope from another import path. Actually, checking more carefully: `torch` is imported and the code uses `nn.DataParallel` without `torch.nn.DataParallel`. The `from utilities import *` star import might happen to pull in something, but this is fragile.

### Design Observations

- **SSAST heritage is very visible.** The code is clearly adapted from Yuan Gong's SSAST codebase. Comments reference SSAST paper equations, the data pipeline is unchanged, and the overall structure (run.py -> traintest.py) follows the same pattern.

- **The "mamba impl" blocks** in AMBAModel are ~40 lines of boilerplate repeated in every forward method. This is the main architectural difference from ASTModel -- instead of `for blk in self.v.blocks: x = blk(x)`, it does the bidirectional forward/backward pass with residual handling and fused norm logic.

- **Joint pretraining (MPC + MPG)** uses a fixed 1:10 loss weighting (`loss = loss1 + 10 * loss2`) which is not configurable via CLI args.

- **No distributed training support** beyond `DataParallel`. There is no FSDP, DeepSpeed, or DDP implementation. `DataParallel` is known to be slower than DDP and does not scale well to multi-node setups.

- **The inference benchmarks are thorough** -- they sweep across a wide range of input sizes (1024 to 151680 frames for AMBA, 1024 to 81920 for SSAST) with 5 runs per size, measuring both time and peak memory. The AMBA range is nearly 2x larger, demonstrating the Mamba model's ability to handle much longer sequences.
